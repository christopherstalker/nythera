# Локальный ИИ и приоритеты Nythera

Проверено 9 сентября 2026 года по текущему коду и официальной документации. Это оценка архитектуры и предложения для следующих итераций; desktop-подключение ниже ещё не реализовано.

## Исправления этой итерации

- Лимит ответа теперь равен минимуму выбранной длины, лимита персонажа и глобального ограничения. Раньше сохранённый глобальный лимит отменял ограничения Short/Medium/Long. Комнаты используют тот же расчёт.
- Gemini больше не получает дополнительные 1536 токенов сверх выбранного потолка. Для поддерживаемых моделей настроен минимальный или отключённый thinking; у моделей с обязательным reasoning он занимает часть общего бюджета. Очень маленький лимит может оставить недостаточно места для видимого ответа.
- Нативные reasoning-модели OpenAI получают `max_completion_tokens`; обычные и совместимые модели сохраняют `max_tokens`. Формирование параметров общее для шлюза приложения и отдельного прокси.
- Числовые поля принимают любые целые значения от 128 до 4096, включая 500 и 1000. Ранее `step=64` блокировал отправку таких значений в форме настроек.
- Отображаемое имя использует существующее поле `User.name`, отдельное от username. Добавлены редактирование, проверка длины/управляющих символов, публичное отображение, обновление сессии и сброс к username при пустом имени. Миграция БД не нужна.

Проверки: 564 теста прошли; TypeScript приложения и прокси, ESLint, форматирование и все pre-commit hooks прошли. Интеграционный тест выполняет оба шлюза с подменёнными ответами провайдеров и проверяет реальные параметры SDK-запросов. Это не проверка генерации с действительными платными ключами. Browser-проверка выполнялась на настоящих компонентах с изолированными API-фикстурами: сохранение имени, неизменный handle, мобильная ширина 390 px без переполнения и сохранение лимита 500. Запись в реальную БД и production-развёртывание не выполнялись.

Скриншоты и вывод проверок находятся в локальной папке `output/roleplay-fixes` и файлах `output/roleplay-fixes-tests-final.txt`, `output/roleplay-fixes-hooks.txt`. Временная страница для проверки панели провайдеров удалена.

## Можно ли подключать локальный ИИ проще?

Да. Формат запросов уже подходит: Ollama и LM Studio поддерживают OpenAI-совместимый API. Проблема — где выполняется запрос.

Сейчас браузер отправляет сообщение в API Nythera, сервер собирает контекст, обращается к провайдеру и сохраняет ответ. `localhost` в этой цепочке относится к машине сервера, а не к компьютеру игрока. Desktop-приложение пока только загружает сайт: его preload передаёт платформу и версию, но не выполняет генерацию.

Это видно в `src/lib/llm-gateway.ts`, `src/lib/safe-outbound-url.ts`, `src/app/api/keys/route.ts`, `src/components/settings/key-settings-client.tsx` и `desktop/electron/{main,preload}.cjs`.

| Вариант                                            | Удобство для игрока                                                   | Что потребуется                                                                        | Рекомендация                                       |
| -------------------------------------------------- | --------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | -------------------------------------------------- |
| Подключение через Nythera Desktop                  | Выбрать Ollama или LM Studio, затем установленную модель              | Локальный транспорт в Electron и разделение подготовки/сохранения хода на сервере      | Основной путь для простого подключения             |
| Текущий Custom provider через публичный HTTPS      | Работает с сайта и телефона, пока компьютер с моделью доступен        | HTTPS-шлюз с аутентификацией, адрес `/v1`, имя модели и ключ                           | Доступный сейчас вариант для опытных пользователей |
| Полностью самостоятельный локальный сервер Nythera | Возможна локальная генерация и хранение                               | PostgreSQL, конфигурация приложения и отдельная политика разрешённых локальных адресов | Позже как поддерживаемый self-hosted режим         |
| Прямой запрос из веб-браузера к localhost          | Не требует desktop, но зависит от браузера и настройки сервера модели | CORS, разрешения локальной сети, CSP, совместимость браузеров, отдельный транспорт     | Не делать основным сценарием первого запуска       |

### Как подключиться через существующий Custom provider

1. Запустить OpenAI-совместимый сервер модели. У Ollama стандартный локальный адрес — `http://localhost:11434/v1`; у LM Studio обычно используется `http://localhost:1234/v1`.
2. Дать Nythera доступ через публичный HTTPS-адрес на порту 443 со шлюзом, проверяющим Bearer-токен. Для LM Studio можно включить встроенную аутентификацию; для локального Ollama её нужно обеспечить перед сервером.
3. В Settings → Models / API keys → Custom provider указать собственный идентификатор провайдера, формат OpenAI-compatible, HTTPS Base URL с `/v1`, точное имя доступной модели и ключ шлюза.
4. Сохранить подключение, обновить каталог моделей и выбрать модель в чате. Проверка подключения использует список моделей, а не только доступность адреса.

Нельзя считать поле API key защитой Ollama: локальный API Ollama сам по себе не требует аутентификации. Необходимо, чтобы ключ действительно проверялся шлюзом. Переключатель `BYOK_ALLOW_PRIVATE_TEST_ENDPOINTS` в коде предназначен для тестов и не является поддерживаемой настройкой подключения в интерфейсе.

### Предлагаемый первый выпуск Desktop-подключения

- Кнопка «На этом компьютере», выбор Ollama/LM Studio и список моделей. Проверять только выбранный loopback-адрес, без сканирования локальной сети.
- Сервер создаёт ход, проверяет владельца и собирает контекст. Desktop выполняет запрос к модели и передаёт поток в чат. Завершение сохраняет ответ по идентификатору хода с защитой от повторной записи.
- Остановка отменяет локальный запрос; сбой сохраняет черновик и предлагает повторить. Проверять обрыв потока, исчезновение модели и повторную отправку завершения.
- Electron предоставляет узкие методы поиска моделей, генерации и отмены. Проверять origin отправителя IPC, главный frame, разрешённый loopback-адрес, путь API, размер сообщения и таймаут. Не предоставлять странице универсальный сетевой прокси.
- Локальные подключения хранить отдельно от облачных ключей и не включать их автоматически в облачный fallback. Переход к платной модели — только выбранное пользователем поведение.
- Явно показывать «Генерация на вашем компьютере; история синхронизируется с Nythera». Полностью офлайн-приватный режим требует локального хранения, поиска памяти, фоновых задач и авторизации; один IPC-мост его не обеспечивает.

Критерий готовности: пользователь с запущенной моделью получает первый ответ без туннеля и ручного ввода Base URL; работает отмена, повтор после сбоя, сохранение единственного ответа и понятная ошибка при выключенном сервере модели. Проверка на реальных Ollama и LM Studio обязательна перед выпуском.

Источники: [Ollama: OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility), [Ollama: authentication](https://docs.ollama.com/api/authentication), [LM Studio: authentication](https://lmstudio.ai/docs/developer/core/authentication), [LM Studio: server start](https://lmstudio.ai/docs/cli/serve/server-start).

## Что должно отличать Nythera

Рабочая гипотеза позиционирования: **длинная РП-история, в которой персонажи сохраняют характер, знают только доступное им и помнят последствия выбора; модель можно менять без потери истории**. Это обещание нужно подтвердить качеством и удержанием пользователей, а не числом пунктов в настройках.

Память сама по себе уже не уникальна. Character.AI описывает память истории, редактируемые автоматически собранные факты и индикатор заполнения памяти. SillyTavern поддерживает lorebooks с динамическим включением контекста. Эти два источника не являются полным обзором рынка и не доказывают отсутствие какой-либо функции у конкурентов. Источники: [Character.AI: Smarter Memory for Smarter Chats](https://blog.character.ai/memory/), [SillyTavern: World Info](https://docs.sillytavern.app/usage/core-concepts/worldinfo/).

В Nythera уже существуют `StoryFact`, `StoryKnowledge`, сцены, ветки, отношения, режиссёр, контрольные точки и экспорт истории. Следующие приоритеты развивают эту основу.

Конкретные найденные ограничения:

- `src/lib/stories/story-foundation.ts` включает полный текст неизвестных актёру фактов с пометкой `NOT KNOWN BY ACTIVE CHARACTER`. Предлагается разделить контекст режиссёра и персонажа, исключая неизвестные секреты из актёрского контекста, включая сводки и извлечённую память. Одной инструкции не раскрывать секрет недостаточно для надёжной изоляции.
- `src/app/api/chats/[id]/branch/route.ts` копирует текущие значения отношений и последний снимок мира. Для ранней точки ветвления нужно восстанавливать состояние именно на момент выбранного хода, иначе поздние последствия могут попасть в прошлое.
- `src/lib/memory/extract.ts` сохраняет текстовую память; это не полноценное автоматическое обновление структурированных предметов, травм и отношений. Завершение сюжетных beats также нужно связывать с реально произошедшим событием.
- Значительная часть story-тестов проверяет присутствие строк и вызовов в исходниках. Нужны также сценарии с реальным состоянием хранилища и отдельно оцениваемые многоходовые ответы моделей.

Это выводы проверки исходников, а не результаты новых запусков моделей. Перечисленные изменения относятся к следующей итерации и не включены в текущие исправления токенов и имени.

### Первый продуктовый эксперимент

Выбрать один жанр и небольшой набор качественных кампаний. Пригласить 15–20 авторов и игроков длинного РП, провести несколько сессий и наблюдать места, где приходится исправлять модель или настройки. Это предлагаемая исследовательская выборка, а не прогноз спроса.

Сначала снять текущий уровень ошибок. Затем сравнить новый сценарий с исходным на одних и тех же моделях, лимитах контекста и историях. В измерениях разделять ошибки приложения и ограничения модели. Не обещать абсолютную безошибочность на любом локальном ИИ.

Основная продуктовая метрика: доля начавших историю пользователей, которые вернулись к той же истории через неделю. Дополнительно — доля сцен без ручной коррекции, повторы генерации, задержка первого токена и стоимость завершённой сцены. Число сообщений само по себе может расти из-за неудачных повторов и не подтверждает качество.

Не расширять сейчас объём голосовых/визуальных эффектов только ради количества функций. Сначала сделать последовательность истории и вход в продукт ощутимо лучше; затем использовать авторские кампании как способ привлечения и возвращения игроков.
